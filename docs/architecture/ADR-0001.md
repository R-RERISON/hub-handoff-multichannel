# ADR-0001 — Handoff Hub como produto independente

Data: 2026-10-15 | Status: ACCEPTED para o baseline

## Contexto
O Tornado atual reúne regras de fila, operadores, integração Teams, anexos, status Finesse e estado em memória. Simplesmente colocá-lo em outro serviço manteria o acoplamento.

## Decisão
Desenvolver produto próprio **API-first e monólito modular**, com workspace independente e múltiplos adapters. Embedded Handoff é o piloto; Native Handoff é evolução. Bot original mantém identidade da conversa; Hub é responsável pelo atendimento. FastAPI e React/TypeScript, SQL Server transacional, workers com outbox/inbox.

## Rejeitado nesta fase
- Centralizar a operação dentro de um bot novo.
- Transplantar o legado Tornado linha a linha.
- Implementar microserviços e broker antes de justificar operacionalmente.
- Vincular núcleo ao SDK Teams, Finesse, Dynamics ou Azure OpenAI.

## Custos e trade-offs
Maior controle e reutilização, porém exige manutenção de produto, testes e sustentação. Não há takeover automático de conversas Teams pertencentes a outros bots; cada adapter tem capacidade e permissões próprias.

## Revisão
Reavaliar após piloto de mensagens ponta a ponta, testes concorrentes e estimativa de custo real.
